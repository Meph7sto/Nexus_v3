# 本机转发与故障演练

从 Nexus V3 仓库根目录运行：

```powershell
pwsh -File ./deploy/data/ha/rehearsal/chain-rehearsal.ps1 -IncludeV2
```

需要 PowerShell 7.4+、Docker Compose、项目 Go 工具链和本地模块缓存。镜像使用本机的 `alpine:3.23`、`postgres:18-alpine`、`redis:8-alpine`。加 `-IncludeV2` 时，脚本从旁边的 `Nexus_v2` 仓库提取固定提交 `57035de2ef0fd5e54984e3648825d9948bab6ffa`，不会读取未提交的源码。加 `-PrepareOnly` 只编译，不启动容器。

脚本运行真正的 Entry 和 Worker 二进制，在独立的 Docker 内部网络中使用合成的用户、Key、PostgreSQL 和 Redis。它不发布端口。SOCKS5 模拟器只接受固定的演练目的地，将连接转给同一隔离容器的 TLS 模拟上游；私有 CA 只在演练容器内信任，生产 URL 校验和 TLS 验证保持开启。脚本退出时仅清理本次创建的资源。

## 对照方法

每组选用同一 Data、同一 SOCKS5 与 TLS 模拟上游，依次运行 V2、V3 关闭 Worker 和 V3 开启 Worker。每组向真实 `POST /v1/responses` 发 3 次请求。每次验证 8 个按序到达的内容片段和最终完成事件，再核对用量记录、计费幂等记录及余额扣减。模拟上游根据实际 SOCKS5 客户端地址分别计数，能区分 Entry 本地转发和两个 Worker 转发。

各组实际扣费均为 0.00011160。首个内容片段计时从客户端发请求开始，整流计时到读完 SSE 为止。每组只有三次请求，且上游时间由模拟器控制；结果用于比较本机走同一路径时的行为，不用于估算生产延迟或 1C 1G 机器容量。

## 非计划退出

同一脚本另含计划停机对照：客户端收到长 SSE 首片后，对 Entry 发送 SIGTERM。验证 Entry 不再接受新连接、旧流继续超过 5 秒，收到全部 80 个内容分片和唯一的完成事件，随后核对 PG 只增加一条用量和一条计费去重记录。此项在本机 Docker 通过，不代表超过配置的停机窗口也能无损。

两个故障场景均先收到在途 SSE 的首个内容片段，再向正在承接请求的测试容器发送 `SIGKILL`。

| 故障 | 在途 SSE | 后续新请求 |
| --- | --- | --- |
| Entry 突然退出 | 本地负载均衡器观察到 `unexpected EOF`，客户端没有收到完成事件 | 负载均衡器在下一请求检查健康并转到第二个真实 Entry。观察到旧流断开后 98 ms 收到首个内容，1.067 s 收到完整新流 |
| Worker A 突然退出 | 客户端没有收到完成事件 | Worker B 承接，新流首内容在观察断开后 82 ms 到达。模拟上游共收到两次请求：旧请求一次、新请求一次，没有重发旧请求或回退 Entry |

时间从测试客户端观察到在途流断开开始。Entry 实验使用请求到达时检查健康的本地负载均衡器；生产负载均衡器的探活策略和故障判定时间需单独测量。

## 受限长流采样

```powershell
pwsh -File ./deploy/data/ha/rehearsal/chain-rehearsal.ps1 -CapacitySample
```

该模式只跑三种转发方式的 4、8 并发，不重复强停演练。Entry 和两台 Worker 各限制 1 CPU、1 GiB 内存，脚本逐一核对容器的实际限额。每轮重建进程与模拟上游，复用同一个 PostgreSQL 和 Redis；每条 SSE 含 40 个合成片段，约 5 秒。驱动核对真实上游同时运行的流数、完整到达的流数及计费结果。

负载窗口内每 250 ms 从各容器的 `/proc/1/status` 读取应用进程的 RSS；VmHWM 表示该进程自启动以来的 RSS 最高值，可能包含启动峰值。进程 RSS 不是容器的总内存，且三进程分别限额，不是整个拓扑共用 1 CPU、1 GiB。
