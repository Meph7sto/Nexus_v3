# 备份恢复与 Data 跨集群迁移

跨集群切换采用单写者流程：旧端停写并完成最后一次备份，整组 Entry 再切向新端。只改同集群连接地址时，先用集群管理页证明两个地址指向同一可写 PostgreSQL 和同一逻辑 Redis，再逐台摘流、重启。

## 本机复验

准备 Docker Compose、PowerShell 7.4+、项目使用的 Go 工具链，以及 PostgreSQL 18 的 `pg_dump` 和 `psql`。准备本地镜像 `postgres:18-alpine`、`redis:8-alpine` 和 [Compose 中固定摘要的 Adobe S3Mock](backup.compose.yaml)。从仓库根目录运行：

```powershell
pwsh -File ./deploy/data/ha/rehearsal/backup-rehearsal.ps1
```

脚本创建新的随机命名项目，包含两套空 PostgreSQL、两套空 Redis 和一个 S3Mock。端口只发布到 `127.0.0.1`，凭据和数据随本次演练生成。无论测试通过还是失败，脚本都清理本次创建的容器、卷和网络。

演练复用 Nexus 的 `BackupService`、S3 客户端、`pg_dump` 与 `psql`、计费仓储及迁移校验逻辑。它用两组真实数据库连接模拟整组 Entry，用受控任务和计费队列模拟停流。备份记录保存在演练进程的独立内存目录中，目标 PostgreSQL 恢复前为空库。故意提交含错误的 SQL，验证恢复退出失败且未留下半套表结构。

## 运维顺序

1. 在集群管理页选择获准的目标配置。核对主库可写、迁移版本与校验和以及 Redis 写入；跨集群预检只生成连接配置，不能证明旧端已冻结或目标数据已追平。
2. 关闭旧 Entry 组的入口流量，停止领取共享后台任务。保留已接单请求的读尾时间，核对待写计费队列、用量日志和幂等记录已落库。不要先杀进程再等队列清空。
3. 停止旧 Entry 进程或在数据层撤销其专用写入身份，验证旧连接和新建连接都写不进去。确认只有保留的运维身份能够读取冻结后的旧库。禁止旧、新 Entry 组同时写 PostgreSQL 或逻辑 Redis。
4. 做最后一次备份，保存备份对象索引及恢复所需的独立凭据引用。在隔离的新库恢复，核验迁移清单、用户、账户、渠道、API Key、订阅、余额、用量和计费幂等记录。逻辑 Redis 另行重建：清除旧会话和并发槽，把需要保留的额度增量先落账再从 PostgreSQL 重建，不把旧 Redis 整库搬过去。
5. 整组 Entry 连接新 Data 后，核对每个实例读取的是同一目标、任务归属唯一、旧端仍拒绝写入。完成只读探测后再打开新端流量，随后用少量受控请求确认计费、额度及幂等性。

## 回退边界

新端未产生权威业务写入时，确认新端已停止写入且两个账本一致，再恢复旧端。新端出现新增或更新后，先停止并隔离新端，将新增数据和计费记录同步、对账。只有旧端已包含全部应保留的写入，而且两边不能同时写，才恢复旧端流量。无法对账时保持写入暂停。

## 本机记录

2026-11-24，使用 pg_dump 和 psql 18.3，S3Mock 兼容端点，两个 PostgreSQL 18 和两个 Redis 8。两次恢复均校验了 317 个迁移文件。

| 取证项 | 观察结果 |
| --- | --- |
| 旧端最终备份与冷恢复 | 78,698 字节。备份上传 366 ms，取回并恢复 1.327 s |
| 冻结至两个 Entry 测试连接核对成功 | 2.284 s。新端写入前，两端业务快照一致 |
| 新端账务 | 用量 3 条，计费幂等记录 3 条；余额 10.34，订阅日用量 0.50，Key 已用额度 2.50 |
| 新端新增后回退 | 隔离新端、备份、恢复并重建旧 Redis 共 2.572 s；3 条已提交用量和对应幂等记录均保留 |

时间包含本机小数据演练的操作，不代表线上 RTO。RPO 结论只适用于本次已提交且核对的三条记录。S3Mock 验证了真实 S3 API 的上传与下载、还原后的数据与迁移校验；未测公有云权限、网络中断、大库压缩或真实 Entry 进程摘流。
